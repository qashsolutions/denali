# Terms & Privacy — Implementation Verification Checklist

> Every feature/behavior claimed in Terms of Service and Privacy Policy (effective March 3, 2026).
> Verify each item is implemented exactly as described. ✅ = verified, ❌ = gap, ⚠️ = partial.

## Authentication & Accounts

- [ ] Account creation requires email + OTP verification (Terms §2, §4)
- [ ] No passive/default acceptance — affirmative action required (Terms §2)
- [ ] Optional TOTP MFA enrollment in Settings (Terms §4, Privacy §8)
- [ ] Account deletion via Settings > Danger Zone (Terms §11, Privacy §7)
- [ ] Admin accounts blocked from self-delete — returns 403 (Terms §11)
- [ ] One account per email enforced (Terms §4)

## Medicare Data Connection

- [ ] OAuth 2.0 + PKCE flow via official Medicare website (Terms §5, Privacy §4)
- [ ] Read-only access — never modifies Medicare records (Terms §5)
- [ ] Revoke connection anytime in Settings (Terms §5, Privacy §4)
- [ ] Scopes limited to Patient, Coverage, EOB only (Terms §5)
- [ ] Never requests/stores Medicare.gov login credentials (Terms §5, Privacy §4)
- [ ] Disconnect immediately deletes all cached health data (Privacy §4)
- [ ] Disconnect deletes OAuth tokens (Privacy §4)
- [ ] Clinical data (conditions, meds, screenings) extracted from claims, not separate FHIR resources (Terms §5)

## Consent Controls

- [ ] 3 toggles in Settings > Privacy & Data: health_data_ai, health_data_storage, analytics (Privacy §4)
- [ ] All toggles default OFF (Privacy §4)
- [ ] health_data_ai OFF → health data stripped before sending to AI (Privacy §4)
- [ ] health_data_storage OFF → no IndexedDB caching of health data (Privacy §4)
- [ ] analytics OFF → trackEvent() returns early (Privacy §4)
- [ ] Toggles changeable anytime, mid-session (Privacy §4)
